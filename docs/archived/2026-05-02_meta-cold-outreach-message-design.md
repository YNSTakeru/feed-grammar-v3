# コールドアウトリーチ メッセージング設計 — 6 罠と Pain Bridge / DFY 強制機構

**抽象化:** 2026-05-01 (`personalization-pain-bridge`) + 2026-05-02 (`cta-free-trial-trap` / `message-iteration-learnings` / `demo-script-frame-collapse-and-subtraction-sales`) の 4 件を統合
**適用範囲:** 5〜10 社規模の B2B コールドアウトリーチ (Webフォーム / メール / LINE) — 文面・CTA・デモ動画台本
**目的:** ユーザーが受け取った瞬間に「テンプレ送信」「商品売り込み」と認識して離脱する 6 種類の罠を、文面確定前に事前検知する
**直交軸:** 実装の質 (`browser-runtime-asymmetry` / `requirement-translation-traps`) と launch 行動 (`launch-procrastination`) と資源管理 (`copilot-operation`) と直交する **顧客接点層 (Customer-Facing Messaging)** の規律

---

## 🧬 前提 — 「動画を見た」だけでは差別化されない

5 社送って 5 社「貴施設 / 貴社」しか変わらない文面を出したケース (`2026-05-01_cold-outreach-personalization-pain-bridge.md`) と、3 つの Pain フレームが全崩壊してテキスト①そのものを廃止した台本反復 (`2026-05-02_demo-script-frame-collapse-and-subtraction-sales.md`) には、共通する構造がある:

| 表層問題 | 深層問題 |
| -- | -- |
| パーソナライズが弱い | **観察 (動画視聴) と記述 (文面) がプロセスでつながっていない** |
| Pain 主張が反論される | **相手のフィールド制約 (動画長さ / 配信先 / 到達経路 / 既導入有無) を確認せずにフレームを設計した** |
| CTA に反応がない | **DIY 構造 (「試してください」) になっており、相手にコストを押し付けている** |
| AI レビューでループする | **モデルが長い会話で「確定削除」を忘れて元に戻すのを横断チェックしていない** |

これら 4 つは独立に発火するのではなく、**観察 → フレーム選定 → 文面化 → CTA → AI レビュー → 確定** のパイプラインで、上流の確認が抜けると下流のすべてが崩れる連鎖構造を持つ。

| # | 罠 | 一言で言うと |
| -- | -- | -- |
| O1 | **フィールド制約未確認 Pain フレーム** | 動画 12 秒なのに「スキップされる」と言って即論破される |

## 罠 O1: フィールド制約を確認せずに Pain フレームを設計する

### 症状 (本事例)

g-carenet 向けデモ動画台本で 3 つの Pain フレームを順次試した:

| フレーム | 主張 | 崩壊理由 |
| -- | -- | -- |
| A: スクロール判断 | 「最初の文字でスクロールを止めるか判断」 | 相手は **能動フロー** (Indeed / YouTube 検索 → クリック)。パッシブ前提で崩壊 |
| B: 音なし視聴 | 「多くが音を出せない環境で視聴」 | 「うちは YouTube だからイヤホンしてますよ」で崩壊 (過去 5/1 で一度却下した角度の再提起) |
| C: スキップ・離脱 | 「単調な画面が続くとすぐにスキップ」 | **相手の動画は 12 秒**。スキップされる前に終わる |

3 フレームすべて、相手のフィールド制約 (動画長さ・配信プラットフォーム・到達経路) を文面確定前に確認していれば 1 個目で却下できた。最終的に Pain 主張そのものを廃止する「引き算」に到達。

### 構造的な原因

- ショート動画 (TikTok/Reels) の論法をそのまま採用動画に転用した
- 「SNS マーケティングの文脈で正しい主張」 ≠ 「採用動画コールドメールで正しい主張」を区別していない
- AI モデルが Pain フレームを強く推した時に、**フィールド制約を渡した上で再評価する** プロセスが抜けた

### 解毒手順 — Pain フレーム設計前 4 項目チェックリスト

文面 / 台本の Pain 主張部分を書く前に、相手の SNS / HP / 動画プラットフォームから以下を確認する:

1. **動画の長さ** (スキップ・途中離脱フレームの有効性)
2. **配信プラットフォーム** (YouTube / Instagram / Indeed 埋め込み — 能動 vs パッシブフロー)
3. **求職者の到達経路** (検索フロー → 能動 / フィード → パッシブ)
4. **相手はすでにテキストオーバーレイを使っているか** (使用 → 「テロップゼロ」フレーム禁止)
5. **コールドメールの受け手のデバイス環境** (イヤホン推定 → 音なしフレームの蓋然性)

1 つでも「Pain フレームと矛盾する」ものがあれば、そのフレームを早期に廃止し**映像に語らせる引き算設計**を検討する。

### 強制機構

`contacts/director.md` (or 同等の営業 SOP) に「Pain フレーム選定前 4 項目チェックリスト」セクションを追加し、未確認項目があれば送信不可とする品質ゲートを設置する。

## 罠 O2: DIY 構造 (「試してください」) は B2B コールドメールでは死ぬ

### 症状 (本事例)

`contacts/director.md` §4 第3文の末尾に「無料でお試しいただけます」と書いた。Grok から「またタダで何か押し売りされるんかって警戒」、Gemini から独立に「DFY (Done For You) 構造が最強」という同方向の指摘を受けた。

### 構造的な原因

- 表面の問題は「無料」という単語に見えるが、根本は **アクションの主体** にある
- DIY (相手が試す) = 相手に学習コスト・操作コストを要求 → 「面倒、後回し」
- DFY (私がやる) = 送り手がコストを払う → 信頼シグナル + コミットメントの証明 + スキルへの自信
- SaaS の「14日間無料トライアル」と同じパターンになり、毎日届く他の SaaS コールドメールと差別化できない

### 解毒手順

第 3 文 (解決提案) を書くとき:

```
❌ 「無料でお試しいただけます」 (DIY)
❌ 「ご利用いただけます」 (DIY)
❌ 「アカウントを作成して〜」 (DIY)

✅ 「テロップ付きで仕上げてお返しします (費用不要)」 (DFY)
✅ 「実際の変化はこちらでご確認ください: [デモURL]」 (変化を見せる)
```

「費用不要」を使う場合は **価値提供の後に括弧で添える** 形にする。先頭に出すと相手の思考が「なぜ無料?後で請求?」に向かう。

### CTA は認知負荷ゼロの 4 点指定

「どの動画を送ればいいか」を相手に考えさせない:

```
❌ 「採用動画の URL を1本送っていただければ〜」
   (相手の心: 長い動画? 短い動画? どこにあるっけ…後回し)

✅ 「YouTube に公開されている直近の採用動画1本を、このメールにコピペして返信してください」
```

指定する 4 点:
1. **どこにある** (YouTube / 自社サイト)
2. **どの動画** (直近の1本)
3. **どうやって送る** (このメールにコピペして返信)
4. **いつ返ってくる** (明日中)

### 強制機構

品質ゲートに以下を追加:
- [ ] 第 3 文に「お試し」「ご利用いただけます」「使ってみてください」等の DIY 構造が含まれていないか
- [ ] CTA が「どこにある / どの動画 / どうやって送る / いつ返ってくる」の 4 点を満たしているか

## 罠 O3: 観察 (動画視聴) と記述 (文面) がプロセスで切れている → テンプレ送信に堕ちる

### 症状 (本事例)

5 社にコールドアウトリーチを送った。動画は見ていた。しかし文面の差は「貴施設 / 貴社」「会社名・URL」のみ。受け取った側は「本当に動画を見たのか、手当たり次第に送っているのか」を判別不能な状態。

### 構造的な原因

- 動画を見ること自体はやっていた
- しかし「**何を見たか**」をメモする仕組みがなく、文面を書く段階でゼロから組み立て直すコストが高かった
- 結果、既存テンプレに施設名を差し込むだけで完了
- パーソナライズの目的を「見た証明」だと誤解 (本来は「機会損失への接続」)

### 解毒手順 — Pain Bridge 4 行記入欄

チェックリスト形式 (「[x] 動画を見た」) は機械的に埋まるだけで本質を捉えない。代わりに **観察結果をストーリー素材として記録する** 4 行記入欄を使う:

```
- 動画で伝えようとしていること:
- 最も印象的なシーン / 伝えたかった場面:
- テロップなしで失われているもの:
- このペインを 1 文で表現すると:
```

この 4 行が埋まれば、director.md §4 の 3 行ブリッジ (意図の承認 → 機会損失 → 解決策) は自然に書ける。

### 3 行ブリッジ構造

```
第 1 文: [相手の動画の意図を承認する]
        — 動画の「意図」を言語化して代わりに言ってあげる (送り手の感想ではなく)
        ❌「職場の温かさが伝わりました」(私の感想)
        ✅「〜というメッセージを伝えようとしてるのだと感じました」(相手の意図の承認)

第 2 文: [その意図が届いていない機会損失を指摘する]
        — 推測形 (「〜とすれば」) ではなく、観察できる事実として書く
        ❌「あのトークが届かないとすれば〜」
        ✅「あのトークがほとんど伝わっていないのが現状です」

第 3 文: [テロップが解決策であることを提示する] (DFY 構造で)
        — 自分の動機 (「解決したくて」) は語らない。相手が次にやること (URL を見る) だけが残る
```

### 強制機構

Pain Bridge 4 行が埋まらないと送信不可とする品質ゲートを `contacts/director.md` §7 に設置する。営業対象社ごとに `contacts/<会社名>.md` を作り、Pain Bridge 4 行を冒頭に明記する。

## 罠 O4: カスケード — 上流テキスト変更時に下流ワーディングを放置

### 症状 (本事例)

デモ台本でテキスト①を廃止した。しかし下流に依存表現が 2 箇所残っていた:

| 表現 | 場所 | 依存していた前提 |
| -- | -- | -- |
| 「**聞かれる前に**取りこぼされています」 | テキスト② | テキスト①「動画が途中スキップされる」前提 |
| 「**スクロールする指を止め**、現場の熱量が伝わる」 | After テキスト | テキスト①「パッシブフローでスクロール中に止まらせる」前提 |

テキスト①を変えた瞬間、これらは「12 秒なら全部聞かれてるよ?」「能動フローでクリックして来た人にスクロール? 矛盾」と即論破される死表現になる。

### 構造的な原因

- 上流のテキストに依存した言葉は、上流を変えた時に下流でも必ず確認・修正が必要
- 文面の各部分を独立に修正しがち (前提依存の連鎖を意識していない)

### 解毒手順 — 横断チェックパス

文面の任意の 1 行を変更したら、変更前に以下をチェック:

```
変更行 → そこで使われている前提 (能動/パッシブ・動画長さ・既導入有無 等) を抽出
       → 同じ前提を仮定している他の行を grep または目視で列挙
       → 全行が変更後の前提と整合するかを 1 行ずつ確認
```

特に **Before / After / トランジション / CTA** は対応構造を持つので、Before の Pain フレームを変えたら After / トランジション / CTA のフレーズが矛盾しないか必ず確認する。

### 強制機構

文面コミット前に「変更行が依存していた前提を 1 行で書き出し、その前提に依存する他の行を列挙する」セルフチェックを `contacts/director.md` §7 に追加する。

## 罠 O5: AI モデルは長い会話で「確定削除」を忘れて元に戻す

### 症状 (本事例)

ラウンド 2 で Grok が「あの大事なトーク」という表現を使った。  
ラウンド 3 でユーザーが「抽象的すぎる」として「あのトーク」に修正・確定。  
ラウンド 4 で Grok が再び「あの大事なトーク」に戻した。

### 構造的な原因

- AI モデルは人間が一度下した削除判断を覚えていない
- 会話が長くなると「承認済みの変更」が無効化されて戻ってくる
- レビューループを回すたびに過去ラウンドの確定済み変更が侵食される

### 解毒手順

- 確定削除した表現・方針は **AI レビューチャットの外** (ローカルメモ / 別ファイル) に記録する
- AI レビュー後に必ず「確定削除リスト」と現在の文面を**横断対照**してチェックする
- レビューループは最大 1〜2 ラウンドで打ち切り (CLAUDE.md §5「レビューループは最大 1〜2 ラウンド固定」と整合)

### 強制機構

`contacts/<会社名>.md` 内に「## 確定削除済み表現」セクションを設け、レビューラウンドごとに更新する。コミット前に必ずそのセクションと最新文面を grep で対照する。

## 罠 O6: 翻案権コンプラ違反 — 相手の動画を勝手に加工して送るのは NG

### 症状 (本事例)

Gemini が「先に相手の動画をテロップ加工して送付する (摩擦ゼロ型)」を提案した。論理的には最強の DFY だが、却下した。

### 構造的な原因

- 日本著作権法上、相手の動画を許可なくテロップ加工 (派生物作成) するのは **翻案権** に抵触する可能性
- 「私的使用のための複製」は許可されるが、第三者に送付する行為は対象外
- たとえ相手が著作権者であっても、**相手が「送ってください」と言う前に加工物を送りつける** のは B2B 信頼構築の観点でも「リテラシーが低い」というシグナル

### 解毒手順

DFY を実現する 2 つの合法ルート:

| 案 | 内容 | 摩擦 |
| -- | -- | -- |
| ✅ A | 先に相手から URL を送ってもらう (暗黙の許可) → 加工して返却 | 1 アクション (URL コピペ返信) |
| ✅ B | 自作素材 (自分で撮影した求人風動画) でデモ動画を作り、メールに貼る | ゼロ (見るだけ) |

5 社規模なら B が現実的 (一度作れば全社共通)。

### 強制機構

品質ゲートに「相手の著作物を許可なく加工していないか」を追加する。デモは原則として自作素材ベースとする。

## 🤖 AI マルチモデルレビューの活用法と限界

### 有効パターン

- **Grok** はコピーライティング的な視点 (弱い言葉・自己中心的動機・推測形) の指摘が鋭い
- **Gemini** は構造的な問題 (DIY vs DFY・カスケード矛盾・認知負荷) の指摘が鋭い
- 2 モデルが**独立して同じ問題を指摘した場合** (例: CTA の「無料でお試し」問題、引き算セールス) は、高確率で本物の問題 → 即修正
- Gemini の「仮説生成」が崩壊フレーム発見につながる (「スキップ」フレーム提案 → 12 秒問題が顕在化)

### 限界 (絶対に超えられない壁)

| 限界 | 例 | 対策 |
| -- | -- | -- |
| AI はフィールド制約 (動画長さ・プラットフォーム) を**自分で確認できない** | 「スキップ」フレームを強く推した | フィールド制約をユーザーが追加してから AI に評価させる |
| AI は長い会話で**確定済み削除を忘れて戻す** | 「あの大事なトーク」復活 | 確定削除リストを別管理 + 横断対照 |
| AI はレビューでループする (項目 A 直す → 項目 B 直す → 項目 A 戻る) | 任意のループ | 最終版前に全項目を一度横断チェック |
| AI の意見は**裁量なしには採用できない** | 「でもでもだけど」逐語引用問題 | 「どちらも一理ある」系は原則に照らして人間が決断 |

## 🔍 既往事例: なぜ防げなかったのか

### ケース 1: 5 社テンプレ送信 (`2026-05-01_cold-outreach-personalization-pain-bridge.md`)

**何が起きたか:** 動画は見たが文面は「貴社/貴施設」しか変えなかった。

**なぜ防げなかったか:**
- 「ちゃんと見ました」を示すためにカスタマイズすると思っていた (パーソナライズの目的の誤解)
- 観察結果を記録する仕組みがなかった (Pain Bridge 4 行が未存在)
- 5〜10 社という少量ターゲットにスケールの発想 (= 効率送信) を持ち込んだ

**回避するために:** 罠 O3 解毒手順 + Pain Bridge 4 行を `contacts/<会社名>.md` の冒頭に必ず書く運用に。

### ケース 2: 「無料でお試し」CTA (`2026-05-02_cold-outreach-cta-free-trial-trap.md`)

**何が起きたか:** Grok と Gemini が独立に「DFY が最強、DIY 構造は警戒される」と指摘するまで気づかなかった。

**なぜ防げなかったか:**
- SaaS 業界の慣習 (「14日間無料トライアル」) を無意識に踏襲した
- 「無料」という単語が問題ではなく「誰が動くか」の構造が問題、という抽象化に至っていなかった
- B2B コールドメールの第一目標 (信頼構築) と SaaS の第一目標 (商品試用) を区別していなかった

**回避するために:** 罠 O2 解毒手順 + 品質ゲートに「DIY 構造禁止」を明記。

### ケース 3: デモ台本 3 フレーム全崩壊 (`2026-05-02_demo-script-frame-collapse-and-subtraction-sales.md`)

**何が起きたか:** Pain フレーム A (スクロール判断) → B (音なし視聴) → C (スキップ) を順次試して全崩壊。最終的に Pain 主張そのものを廃止する「引き算」に到達。

**なぜ防げなかったか:**
- 動画の長さ (12 秒) を Pain フレーム選定前に確認していなかった (フィールド制約未確認)
- ショート動画 (TikTok/Reels) の論法を採用動画に転用した (コンテキスト混同)
- フレーム B は過去 5/1 で一度却下した角度の再提起だった (= **AI モデルが「却下済みフレーム」を覚えていない** = 罠 O5 の派生)

**回避するために:** 罠 O1 解毒手順 + Pain フレーム選定前 4 項目チェックリスト。さらに「過去却下したフレーム」を `contacts/<会社名>.md` の「## 却下済みフレーム」セクションに記録する。

### ケース 4: 「あの大事なトーク」復活 (`2026-05-02_cold-outreach-message-iteration-learnings.md`)

**何が起きたか:** ラウンド 3 で確定削除した「大事な」がラウンド 4 で AI によって戻された。

**なぜ防げなかったか:**
- AI レビューチャットの中だけで削除判断を保持していた (記憶層の単一化)
- ラウンド数が 5〜6 に増え、AI のコンテキスト容量を超えた
- 最終版の前に全項目を横断チェックする習慣がなかった

**回避するために:** 罠 O5 解毒手順 + 確定削除リストを別ファイル管理 + 横断対照。

# director.md (プロダクトの北極星 + 検証装置)

本ファイルは **feed-grammar-v3 のゴールと検証装置** を定義する。
判断軸 (実装方針 / 継続規律 / 資源管理 / スキル起動規律) は CLAUDE.md §1〜§5.6 を参照。
本ファイルは「**何のために作るか / それが正しいと半年後にどう証明するか**」だけを書く。

---

## 1. コアバリュー (主軸)

CLAUDE.md §1 の北極星を再掲する:

> 「半年後、画面に英語しか出てなくて初めて自分の成長に気づく」
> 補助輪 (カタカナ読み) が音もなく消えていたという**自己発見**が UX の頂点。

実装ターゲット:
- ネイティブの自然な音声変化 (reduction / linking / elision) を、カタカナ → IPA → 英綴り の段階 morph (CLAUDE.md RULE D-2) でユーザーが「聞こえる」状態へ運ぶ
- Whisper ASR で発話一致率を計測し、ステージ進行を駆動する
- 補助輪 (カタカナ表記) は自動的・段階的に消えていく。ユーザーは消えたことに後から気づく

## 2. 独自 KPI (アプリ内で完結する定量指標)

外部試験ではなく、**アプリ内でしか測れず、英語力向上と相関する** 3指標を主たる成功指標とする:

1. **補助輪依存度低下率** — カタカナ表記の表示秒数 / 全セッション秒数 が時間経過でどれだけ下がるか
2. **累計浴び単語数** — Whisper ASR で実際に聞き取れた (一致率 X% 超) 英単語の累計
3. **ASR 一致率の中央値** — ユーザーの発話と citation IPA の一致率 (segment 単位中央値)

各指標の閾値と計測実装は spec/ で個別定義する (本ファイルでは閾値を固定しない)。

## 4. 【付録】外部検証マイルストーン: 英検4級リスニング

**本付録の機能・データは、プロダクトのコアロジック (§1〜§3 / RULE D-1 / RULE D-2) に 1 ミリも干渉させてはならない。**

### 4.1 検証仮説

> 「§1 のコアバリュー (Morph による Reduction/Linking 聞き取り訓練) を満たしたユーザーは、
> **英検4級リスニングの試験対策 (過去問演習等) を一切行わなくても、リスニング正答率 70% 以上を取れる**」

合否ではなく **リスニング正答率** を指標にする (筆記の試験形式バイアスと分離するため)。

### 4.2 受験予定

- 受験者: 自分一人
- 想定受験回: 2026 年度 第 2 回 (10 月) 一次試験
- 申込時点で受験料 (4,000 円台) を払う = サンクコストでコミット装置にする

### 4.3 スコープ外 (本アプリでは扱わない)

- 筆記試験 (語彙穴埋め / 短文読解): v0 は動画リスニング体験に専念。語彙・文法は副次的にしか身に付かない可能性を許容する
- 試験直前 (受験前 2〜4 週) の過去問演習 (筆記): **アプリ外で行う**。これは妥協ではなく規律 (アプリの主軸を試験対策に滑らせないため)

### 4.4 検証プロトコル

合格 / 不合格だけでは因果が出ないため、以下を併走させる:

1. **v0 着手前 sanity check (15 分)**: 4級過去問リスニング 5 回分を聞き、reduction / linking 発生頻度を観測。所感を `knowledegs/` に日付付きで残す
2. **受験前 30 日間: 1 日 1 行の自己申告ログ** — アプリ内利用時間 / アプリ外英語学習時間 (過去問演習・他アプリ・YouTube 視聴等) を分けて記録
3. **受験後: 結果と過去ログの相関を `knowledegs/` に分析**
   - リスニング正答率 ≥ 70% かつアプリ外時間 ≪ アプリ内時間 → 仮説支持
   - 正答率 ≥ 70% だがアプリ外時間 ≫ アプリ内時間 → 効果分離不能 (引き分け扱い)
   - 正答率 < 70% → 仮説反証 / director.md 改訂のトリガー

### 4.5 受験結果による director.md 改訂条件

- **支持された場合**: 他人に語る根拠を獲得。北極星をそのまま v1 へ持ち越し
- **反証された場合**: §1 コアバリューの前提 (Morph で reduction が聞こえるようになる) が誤っていた可能性。director.md を全面改訂

## 5. データスキーマ規律 (CLAUDE.md RULE D-1 を再掲)

`feed-data.json` / transcript JSON schema への追加は以下のルールに従う:

- **永久 BLOCK**: 試験固有名称メタデータ (`eiken_4th`, `toeic_400` 等)
- **許可 (条件付き)**: CEFR 等の**汎用抽象基準**メタデータ (`difficulty_level?: "A1" | "A2" | "B1" | "B2" | "C1" | "C2"` / `tags?: string[]`)
- **必須**: 型定義なしのフィールド追加は BLOCK (`types/` に TS 型を追加してから JSON に追加)

`feed-data.json` に英検固有フラグが侵入した瞬間、本 director.md の §4 付録規律は破綻したものとみなす。

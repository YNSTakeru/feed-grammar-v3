# Copilot Pro+ 運用 — 週制限 / AI Credits 制で 1 ヶ月持たせる原則と強制機構

**抽象化:** 2026-05-01 (`/office-hours` セッションで Copilot Pro+ の現運用 (Sonnet 4.6 HIGH = 仕様 / GPT-5.3-Codex XHIGH = 実装 / Opus 4.7 = souls 更新) が、**強制機構なしの原則** 状態で、5/3 launch まで + 6/1 の AI Credits 従量制移行を跨いで 1 ヶ月持たない可能性が判明)
**適用範囲:** Copilot Pro+ ($39/月 = 3,900 AI Credits/月) を使う全セッション。5 月は週制限 (premium requests / 7 日間 token 上限) 制、6/1 以降は AI Credits 従量制
**目的:** 「重いモデルに渡す入力を極小化」「`/clear` と `/model` を物理的な切替操作として定着」「死蔵原則を強制機構で再発防止」の 3 点を CLAUDE.md と直結させ、月予算を尽くさず launch まで届かせる
**関連:**
- `souls/2026-04-27_meta-launch-procrastination.md` (罠 P1: 技術判断を launch ブロッカーに偽装) — RTK 等の外部圧縮ツール導入は本書では launch 後扱い
- `souls/2026-04-26_meta-task-graph-execution-discipline.md` (BLOCK 化原則は強制機構なしには再発する) — 本書の強制機構 2 点 (`/clear` 発火条件 / 出力末尾 `/model` 誘導テンプレ) はこの原則の直接適用
- `copilot_operation/doc1.md`〜`doc4.md` (本書の前提となる料金体系・モデル別単価・節約戦略の調査資料)

## 🧬 前提 — 「実装の質」「launch 行動」「資源管理」は直交 3 軸

| 軸 | 守るもの | 関連 souls |
| -- | -- | -- |
| 実装の質 | 実機で壊れない / spec 通り | `meta-browser-runtime-asymmetry` / `meta-requirement-translation-traps` 他 |
| launch 行動 | 期日に届く / 技術判断で止まらない | `meta-launch-procrastination` |
| **資源管理 (本書)** | **月予算を尽くさず 1 ヶ月持たせる** | **本書** |

3 軸はすべて独立に発火する。実装が完璧で launch も期日通りでも、**月の半ばで Copilot が動かなくなれば残作業はゼロ進捗** になる。本書はこの第 3 軸専用。

### 移行スケジュール

| 期間 | 課金体系 | 主な制約 |
| -- | -- | -- |
| 〜2026-05-31 | premium requests + 週次 token 上限 | 「回数」と「7 日間トークン合計」 |
| 2026-06-01〜 | AI Credits 従量制 ($39 = 3,900 credits/月、超過は追加課金) | 「金額相当の消費量」、自動追加課金 OFF が前提 |

5 月は **週制限到達=その週は止まる**、6 月以降は **残高 0 + 自動追加 OFF=その月は止まる**。性質が違うが、「重いモデル × 長文脈 × 並列 × 自走」という消費パターンが共通の地雷である点は同じ。

## 🚨 Copilot 5 罠 (C1〜C5)

### 罠 C1: 「とりあえず賢いモデル」癖

#### 発火パターン

新しいセッションを Sonnet 4.6 HIGH または Opus 4.7 で開いて、その後の **軽作業 (typo 修正 / 1 行追加 / コミットメッセージ生成)** までそのモデルで処理する。

#### 実体

Claude Sonnet 系は出力 $15/1M token、Opus 4.7 はさらに高単価。GPT-4.1 / GPT-4o / GPT-5 mini は paid plan で **premium request を消費しない** のに、それを「軽作業用に開き直す手間」を惜しんで毎回高単価モデルで処理すると、月の半ばで credits が尽きる。

#### 構造的な原因

| 要因 | 機序 |
| -- | -- |
| **モデル切替の手数コスト** | `/clear` → `/model` の 2 操作が「面倒」として無意識に省略される |
| **「賢い方が安全」幻想** | 軽作業は Sonnet でも GPT-4.1 でも結果が変わらないが、結果同一性を毎回検証していないので「念のため」高単価を選ぶ |
| **セッション継続の慣性** | 1 セッションで複数粒度のタスクを混ぜる癖 (C2 と連動) |

#### 解毒手順

1. **タスク種別を分類してからモデルを選ぶ** (下記モデル選択マトリクス参照)
2. **モデル切替時は必ず `/clear` を打つ** (強制機構 1)
3. **セッション末尾で次タスク推奨モデルを宣言する** (強制機構 2)

---

### 罠 C2: コンテキスト無限積み上げ

#### 発火パターン

1 セッションを `/clear` せずに引き継ぎ続け、CLAUDE.md / 既存 spec / souls / 過去会話履歴が毎ターン全て再送信され、入力 token が雪だるま式に膨張する。

#### 実体

GitHub Copilot は **キャッシュ入力が安い (通常入力の 1/10)** が、新しい質問が来るたびに会話全体が「新規入力」として再カウントされやすい (実装はモデル依存)。20 ターン続いたセッションは、**最初の 1 ターンの 20 倍以上のトークン** を 1 回の応答で消費していることがある。

#### 構造的な原因

| 要因 | 機序 |
| -- | -- |
| **会話の流れの惜しさ** | 「ここまで状況説明したのにリセットしたくない」感情が `/clear` を阻む |
| **暗黙の続行癖** | タスク完了 → commit の後、次タスクを同じセッションで始める習慣 |
| **コンテキスト=価値の誤認** | 長い会話履歴が「賢い応答を保証する」と思い込む (実際は逆 — 古い情報がノイズ化する) |

#### 解毒手順

1. **強制機構 1 (`/clear` 発火条件 4 種) を機械的に実行**
2. **CLAUDE.md / souls 全文添付禁止** (CLAUDE.md §7 既存ルール + 本書再強調)
3. **新セッション冒頭は「タスク種別 / 触るファイル / 完了条件」の 3 行で開始**

---

### 罠 C3: エージェント自走の野放し

#### 発火パターン

GPT-5.3-Codex XHIGH に「このバグ直して」とだけ投げ、対象ディレクトリ / 探索回数上限 / 停止条件を切らずに自走させる。Codex が grep → read → grep → read → 試行 → 試行 を 30 回繰り返して 1 回の応答で credits を一気に消費。

#### 実体

エージェント型モデルは **自律試行回数 × 1 回あたりの入出力 token** で消費が掛け算的に膨らむ。Copilot 公式も「並列ワークフローを減らす」「停止条件を明示する」を推奨している (`copilot_operation/doc1.md` / `doc4.md`)。

#### 構造的な原因

| 要因 | 機序 |
| -- | -- |
| **「賢いモデルなら勝手に解決する」期待** | 制約を切らないことが「自由度を与える=賢さを引き出す」と誤認 |
| **試行コストの不可視性** | 1 回の応答が裏で何往復したかの体感がない |

#### 解毒手順

1. **Codex / Agent モードを使うときは必ず以下を明示**:
   - 対象ディレクトリ (`src/components/X` など)
   - 触ってよいファイル / 触ってはいけないファイル
   - 探索回数上限 (例: 「grep は 3 回まで」)
   - 成功条件 (例: 「`pnpm test` 通過」)
   - 失敗時の停止条件 (例: 「2 回試行して直らなければ報告のみ」)
2. **大きな変更は Plan Mode で先に計画を固めてから実装フェーズに切り出す** (`copilot_operation/doc4.md` Phase テンプレ参照)

---

### 罠 C4: 同じ前提を毎セッション貼り直す

#### 発火パターン

新セッション冒頭で CLAUDE.md / 関連 souls / 関連 spec を全文ペーストする癖。本来 CLAUDE.md は **常時自動添付** (Copilot の repository instructions として) されるはずなのに、「念のため」全文を再添付する。

#### 実体

CLAUDE.md は repository instructions として自動添付される構造になっている (本ファイル自身)。手動再添付は二重送信であり、純粋な無駄。

#### 構造的な原因

| 要因 | 機序 |
| -- | -- |
| **自動添付の信頼不足** | repository instructions 機能の挙動を毎回確認していないので「念のため」貼る |
| **コピペ習慣の固着** | 過去の習慣が消費構造の変化を上書きする |

#### 解毒手順

1. **新セッション冒頭は「タスク種別 / 触るファイル / 完了条件」の 3 行のみ** (C2 解毒と同じ)
2. **CLAUDE.md / souls / spec への参照は「ファイル名 + 該当セクション番号」で渡す** (例: 「CLAUDE.md §3 罠 P1 参照」)。全文添付しない
3. **どうしても context 必要なら `#file:` のようにファイル参照で**、ペーストはしない

### 罠 C5: モデル切替忘れ (セッション横断)

#### 発火パターン

souls 更新で Opus 4.7 を起動 → souls 更新完了 → 次の実装タスクを **そのまま Opus で開始**。逆も同じで、Codex で実装中に「ついでに souls の方針メモも更新」を Codex に投げて思考の質が落ちる。

#### 実体

モデル切替は手動操作が必要だが、`/clear` を打たないと前タスクのコンテキストが残ってモデル切替の動機自体が薄れる。結果、**全タスクが起動時のモデル** で処理される。

#### 構造的な原因

| 要因 | 機序 |
| -- | -- |
| **タスク切替時のモデル再選択忘却** | 完了 → 次タスク開始の遷移で、モデル選択ステップが省略される |
| **末尾誘導の欠如** | 「次は何モデルで」を出力末尾に書く習慣がない |

#### 解毒手順

1. **強制機構 2 (出力末尾 `/model` 誘導テンプレ) を全タスク完了出力に必須化**
2. **`/clear` と `/model` はセットで発火** — `/clear` した直後に `/model <model>` を打つ運用に固定

## 🛡️ 強制機構 (CLAUDE.md に grep 検証可能な形で記載)

### 強制機構 1: `/clear` 発火 4 条件

以下のいずれかを満たした瞬間、議論や次タスク説明より先に **即 `/clear`**:

1. **タスク完了 (`git commit` 直後)**
2. **モデル切替 (Sonnet → Codex / Opus → 他、いずれの方向でも)**
3. **セッション内ターン数 20 超** (体感は「会話が長くなってきたな」)
4. **話題が当初目的から逸れた瞬間** (例: 実装中に「そういえば設計の話だけど」が出たら `/clear` → 別セッション)

検証方法: タスク完了報告の commit と次セッションの commit が **連続していない (clear で session が切れている)** こと。同一 session 内で複数 commit がある場合は罠 C2 発火の証跡。

### 強制機構 2: 出力末尾 `/model` 誘導テンプレ

**全タスク完了出力の末尾** に以下を必ず付ける:

```
---
次タスク推奨モデル: <Sonnet 4.6 HIGH | GPT-5.3-Codex XHIGH | Opus 4.7 | GPT-4.1>
理由: <仕様策定 / 実装 / souls 更新 / 軽作業>
推奨手順: /clear → /model <model> → 次タスク開始
```

検証方法: タスク完了報告に上記 3 行が含まれているかを grep (`rg "次タスク推奨モデル"` で件数確認)。

## 📋 モデル選択マトリクス

| タスク種別 | 推奨モデル | 理由 |
| -- | -- | -- |
| 仕様策定 / 複雑タスク分解 / 設計レビュー / 難デバッグ | **Sonnet 4.6 HIGH** | 思考深さ/コスト比が最良。Opus はオーバーキル |
| 実装 / 差分生成 / リファクタ / バグ修正 | **GPT-5.3-Codex XHIGH** | コード生成に特化、Sonnet 系より安価。停止条件必須 (C3) |
| 軽い質問 / 短い補完 / 要約 / コミットメッセージ | **GPT-4.1 / GPT-5 mini** | paid plan で premium request 消費なし |
| souls 更新 / 全体効率化 / メタ判断 / 横断推論 | **Opus 4.7** | 横断推論が必要な時のみ。souls 更新後は即 `/clear` (C5) |
| 制限近接時 / 通常作業 | **Auto** | 軽量モデルに自動逃避、10% 割引 (`copilot_operation/doc3.md`) |

## 📅 月次 / 週次運用 (5 月) と (6 月以降) の差分

### 〜2026-05-31 (週制限期)

- 月初: premium request の月間枠 (1,500 件) を確認
- 週次: 7 日間 token 消費の体感を記録 (週末に「今週 Opus 何回使った」を 30 秒メモ)
- launch (5/3) までは **Opus は本書 / souls 更新 / 全体効率化のみ**、それ以外は Sonnet/Codex/GPT-4.1 で完結
- launch 後の最初の 1 週は反応データ収集 (罠 P3) のため Opus 使用ゼロを目標

### 2026-06-01〜 (AI Credits 従量制)

- 月初: 残高 3,900 credits を確認、**自動追加課金 OFF を確認** (`copilot_operation/doc1.md`)
- 週次: 残量レビュー (1 週あたり目安 900 credits 以内)
- セッション開始前に **タスク粒度を見積** — 「1 セッション 100 credits 以内」が経験則の目安 (実測で再キャリブ)
- credits 残 500 を切ったら **Opus 完全停止 + Auto 強制** で月末まで延命

数値はあくまで目安。6 月の最初の 1 週で実消費を測ってから本書を再キャリブレーションすること。
